# Security and dependency review

Current release 1.2.0 dependency status: full and production `npm audit` both report **zero known advisories** in the current installed graph. The older counts below are retained as history. See the 1.2.0 follow-up for the independent local codec replacement, compatibility limits and remaining verification boundaries; a registry audit is not security certification.

Read-only service; no signing, wallet connection, key storage, arbitrary RPC URL inputs, user-uploaded JSON/TOML or token metadata HTML. Fixed configured RPC endpoints, address/network allowlist, bounded responses/accounts, timeouts, concurrency limit 8, 20 inspections/IP/minute and 20-second cache. React escapes evidence strings. RPC details are not returned on infrastructure failures. API secrets stay server-side. Unknown RPC routes return JSON404.

`npm audit --omit=dev` on 2026-10-08 reported **13 affected packages: 6 high, 7 moderate** (counts include dependency propagation). Outstanding roots: `bigint-buffer` buffer overflow (GHSA-3gc7-fjrx-p6mg) via SPL Token; `toml` recursion/prototype pollution via Anchor (GHSA-82x6-q7mm-w9cf, GHSA-v5mp-jgw5-2x6j); `stream-json` resource/prototype issues and `uuid` output-buffer bounds via web3.js/Jayson. npm proposes incompatible SDK-adjacent major changes; no force-upgrade was applied.

The service does not parse user TOML or use user-supplied UUID buffers. RPC JSON uses web3.js and bounded HTTP responses; bigint/token decoding remains an upstream attack surface despite data bounds and owner checks. This is **not a clean audit or proof of unreachability**. Use trusted RPC infrastructure, keep the process isolated/non-root, monitor upstream SDK fixes, and review compatible updates before public launch. No end-to-end cryptographic chain verification is performed; RPC trust remains.

Optional Google-hosted fonts are external network requests and may fall back to Arial/monospace. Self-host fonts if deployment policy requires no third-party requests.

## Release 1.1.0 follow-up — 2026-10-08

The original dependency findings above remain open: **13 affected packages, 6 high and 7 moderate**. Production now starts with `node --no-addons --import tsx server/index.ts`, disabling native addons without spawning an unprotected child Node process. This mitigates the native bigint-buffer binding path by using the JavaScript fallback. It does not establish that all affected packages are unreachable or provide a clean audit. Build tools run under normal Node settings; do not globally force `--no-addons` for the build.

The reader validates both SDK account families: `virtualPool` / `poolConfig` and `transferHookPool` / `configWithTransferHook`, including matching config family, pool derivation and account ownership. Transfer-hook metadata is disclosed; hook behavior and extension parameters are not audited. Standard and transfer-hook-family real mainnet examples were verified. Future account formats and every possible pool state are not guaranteed.

Recommendation exports now retain the complete report, including schema, network, timestamp, slot, raw read context and synthetic marker. Browser request cancellation and generation checks prevent a stale live response from replacing a later mode/input choice. PNG cards include all finding counts, and unknown-extension summaries consistently describe uncertainty.

API controls include a hard cap of 5,000 expiring IP buckets, 8 active reader jobs, shared pending reads, a 20-second bounded cache, a 50-second inspection deadline and propagation of client cancellation to upstream fetch. An unresolved underlying job retains its concurrency slot, preventing timeout from silently allowing unbounded work. CSP restricts scripts to the same origin; submission copy buttons use a separate static script.

Validation: **33 passing tests** across assessment math, encoded RPC fixtures, reader decoding/ownership/PDA/extension/fallback paths, timeouts/cancellation, API validation/cache/rate bounds and frontend export/request helpers. TypeScript and production build pass. These tests improve regression evidence; they do not replace a penetration test, independent chain verification or an asset audit.

## Release 1.2.0 follow-up — 2026-10-08

The vulnerable native bigint-buffer implementation is replaced throughout the dependency graph by an independent local pure-JavaScript codec (`vendor/bigint-buffer`). This is not an upstream fixed release or a renamed copy of vulnerable native code. The replacement implements only the four functions used by Solana layout utilities, has no dependencies/native addons/install scripts, bounds widths to 1,024 bytes, and rejects negative or overflowing values. Tests check actual installed resolution, byte vectors, boundary widths, round trips and SPL layouts. Compatibility with arbitrary upstream consumers is not asserted.

Targeted overrides select `toml` 4.2.0 and `jayson` 5.0.0. Compatibility tests exercise Anchor's Buffer-based TOML parser and web3's actual browser-client RPC path. Independent clean installation reproduced the dependency setup. Full `npm audit --json` and production `npm audit --omit=dev --json` now report zero known advisories; zero registry findings do not prove absence of vulnerabilities in local code or dependencies. Production retains direct `--no-addons --import tsx` startup as defense in depth; build tools use normal Node settings.

Input resolution distinguishes the shared DBC authority/program from pool addresses, wallets, configurations and token-holding accounts. Token mint lookup uses exact family and base-mint filters, zero-byte data slices, bounded responses and at most eight candidates. Every candidate undergoes full reader validation and base-mint matching. Multiple matches require explicit selection. No user-selected RPC URL or unfiltered whole-program scan is exposed.

RPC endpoint lists are operator-controlled, ordered and capped at four. Transient retries share a 45-second operation deadline and respect cancellation; each fetch bounds response bytes and body-read time. The API's outer deadline limits the full discovery/inspection path. Helpful non-transient errors are not offered a Retry action. These controls do not eliminate trust in RPC observations or provider availability.

Official public mainnet/devnet RPC hosts share a process-wide 2-requests/second scheduler and a maximum queue of 64. Queue waiting respects cancellation. HTTP 429/503 can impose a bounded 1–10 second Retry-After cooldown, with retry backoff inside the operation deadline. Operators can configure `RPC_REQUESTS_PER_SECOND`; private endpoints are unpaced by default but remain subject to API concurrency and deadlines. Final upstream 429 is relayed as HTTP 429 with bounded Retry-After and provider-safe guidance. A temporary discovery-provider 503 is retryable; invalid addresses and ambiguous selection are not.

Final local validation: 76 passing tests and normal production build. Explicit deadline regressions verify that short deadlines interrupt long retry/cooldown waits and that cancellation stops queued work. The final runtime fully inspected 100 unique real mainnet pools with zero errors: all returned 8 checks and 100% available-check coverage. The sample included 99 standard and 1 transfer-hook pool, with 93 DAMM v2 and 7 DAMM v1 destinations, and deliberately seeded legacy-fee, variable-supply/USDC and active Token-2022 cases. This evidence supports sampled execution paths; it does not certify assets, hook behavior or every future layout. Linux staging independently reproduced production installation with zero known advisories and health release 1.2.0. Public cutover is an operational check, separate from these test results.
