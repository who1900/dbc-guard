### F1 — Medium: recommendation export provenance

Reproduction: inspect a pool on either network and export review recommendations. JSON contains address, synthetic marker and findings, but omits network, timestamp, slot and schema version. An exported address cannot identify the network or snapshot on its own. Methodology promises provenance for every JSON export. Main report JSON retains provenance; this defect applies specifically to recommendations.

Suggested addition to the export object (not applied):

```ts
schemaVersion: report.schemaVersion,
network: report.network,
inspectedAt: report.inspectedAt,
slot: report.slot,
```

### F2 — Low: pending request versus demo selection

Reproduction: throttle API response, click Inspect, then Explore synthetic demo. The demo button remains enabled; a late successful response unconditionally sets the live report and replaces the user's later choice. A late error can coexist with the synthetic report. Network and synthetic labels remain present; this is a state/UX race, not silent fabricated chain data.

Minimal suggested fix (not applied):

```tsx
<button disabled={loading} onClick={showDemo}>Explore synthetic demo →</button>
```

A request identifier or AbortController can instead discard stale results when changing modes.

### F3 — Low: PNG omits caution and unknown counts

Reproduction: export a PNG from a report with cautions or unknown checks. The card shows coverage, known-risk count and the full verdict; it lacks the other counts shown by the main interface. **The preserved verdict still communicates cautions/incompleteness**, so this is incomplete summary context, not a claim that all risks are hidden.

Suggested export line (not applied):

```ts
`${risks} risks · ${cautions} cautions · ${unknown} unknown`
```

### F4 — Low: contradictory unknown-extension summary

Reproduction: an extension list containing `Unknown(99)` produces unknown status, but the summary can still read “No policy-sensitive base-token extensions detected.” The status is correct; explanatory text should reflect unsupported interpretation.

Suggested branching (not applied):

```ts
const unknownExtensions = mint?.extensions.some(x => x.startsWith('Unknown'));
const summary = unknownExtensions
  ? 'Unsupported extension types; policy unknown.'
  : existingSummary;
```

### F5 — Medium: reader integration test gap

The 14 tests cover assessment math, address/owner validation, normalization and an oversized RPC response. They do not call the full `readReport` flow against controlled RPC replies to verify invalid discriminators, decoded pool/config linkage, PDA mismatch, uninitialized mint, unknown/malformed TLV, mint-fetch fallback or RPC timeout behaviour. Source validation exists; the gap is regression evidence, **not a confirmed bypass**.

Suggested test approach (not applied): mock the configured RPC's `getAccountInfo`/`getMultipleAccounts` responses with encoded fixture accounts, invoke `readReport`, assert malformed pool/config/PDA inputs reject, and assert mint transport/decoding failure preserves the partial report with three unknown mint checks. Add a hanging-fetch timeout case. Keep live smoke separate from deterministic fixtures.

Express trusts loopback proxy hops; supplied Nginx replaces forwarded IP with actual client address. Another proxy topology requires a new trust-policy review. No wallet authentication, signer/owner authorization of transactions, CPI, escrow, reentrancy or private-key custody is exercised: those financial-program security classes are **N/A**, not passed audits.

### Dependency advisories — separate from confirmed findings

Both full `npm audit --json` and production `npm audit --omit=dev --json` reported **13 affected dependency packages: 6 high, 7 moderate, 0 critical**. Counts include propagation through SDK/Anchor/SPL/web3; they do **not** mean six exploitable server vulnerabilities. Roots include bigint-buffer buffer overflow, toml recursion/prototype pollution, stream-json resource/prototype issues and uuid bounds issues. Exploitability through this application was **not verified**. Source does not parse user TOML or supply user UUID buffers, but that is not proof of unreachability. Review compatible upstream fixes; do not force incompatible SDK upgrades. See `SECURITY.md` for advisories and mitigations.
