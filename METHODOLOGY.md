# Assessment methodology v1

Pinned Meteora SDK: 1.5.13. Pool/config owner, discriminator/layout and derived pool PDA are checked before interpretation. Each fetch has 12-second timeout, 1 MiB response limit; account buffers are bounded to 64 KiB. Token owners and initialization are validated. Upstream failure never yields fabricated live data.

1. **Mint authority:** absent → no flag; DBC PDA → caution for program-controlled supply; other authority → risk. Actual mint state takes priority over configured intent.
2. **Freeze authority:** present → risk; absent → no flag; missing mint → unknown.
3. **Base token extensions:** transfer fees/hooks, delegate, freezing/default state, nontransferability, confidential transfers, pausing, permissioned burn, mint close, interest/scaled UI → caution. Unknown extension types → unknown. Metadata-only extensions do not alone flag. Extension parameters and quote token policy remain outside scope.
4. **DBC trading fee ceiling:** scheduler cliff numerator plus maximum configured dynamic component; `getTotalFeeNumerator` uses denominator 1e9 and caps at 99%. Active rate limiter can approach cap, so cliff is not reported as maximum. Above 300 bps → caution; above 1000 bps → risk. Heuristics are tool policy, not Meteora safety guarantees. Migrated pools show historical DBC ceiling and configured migrated fee; no current DAMM quote is inferred.
5. **LP migration allocation:** six buckets (partner/creator liquid, permanent and vesting) must sum to 100. Configured liquid allocation is disclosed separately. SDK lock helper evaluates time zero and day one using rounded hypothetical liquidity; those time-based values are estimates. Thresholds allow 0.02 percentage points for two vesting buckets' integer rounding: unlocked above50.02% → risk, unlocked above0.02% or day-one lock below49.98% → caution. This prevents exactly50% configured unlocked liquidity becoming a majority-risk flag from SDK roundoff. These are configured allocations, not verified current DAMM positions.
6. **Creator allocation:** vesting amount = amountPerPeriod × numberOfPeriod + cliffUnlockAmount using BN. Fixed lifecycle denominator is configured post-migration supply; dynamic denominator is swap + migration + vesting allocation. Above 20% creator vesting → caution. Fixed supply less than allocated amounts → unknown; positive configured leftover estimate → caution. Leftover estimate is not claimable vault balance. Wallet holdings are not measured.
7. **Curve:** active prefix stops at first zero boundary/liquidity. Increasing boundaries/positive liquidity are required. Price amplification uses migrationSqrtPrice²/startSqrtPrice², not terminal sentinel. Above 100× → caution heuristic; not evidence of discontinuous pricing. Liquidity values are disclosed; a low-liquidity segment is not asserted unsafe without trade-size simulation.
8. **Migration:** quote reserve / threshold in raw BN units, capped before number conversion. `isMigrated` is authoritative; 100% reserve without flag means pending. MigrationOption 0 = legacy DAMM v1, 1 = DAMM v2. Missing quote decimals displays raw units; unknown threshold/destination is unknown.

Unknown checks lower coverage and prevent a no-flag verdict. Risk takes precedence over incomplete coverage; UI still displays coverage. No flag means no configured threshold triggered among assessed evidence, never "safe". Each exported JSON carries provenance, timestamp, network, slots, synthetic flag and decimal raw fields. Synthetic demo is an illustrative fixture, not proof of mainnet behavior.

## Input resolution and transport — release 1.2.0

The input can be an individual DBC pool or initialized token mint on the chosen network. The shared DBC pool authority and executable program address are recognized before network lookup; neither identifies an individual pool. Wallet/system accounts, configuration accounts, holding accounts and other protocols' pools receive specific input guidance. These errors are not retried as transport failures.

Token discovery uses `getProgramAccounts` with both exact SDK pool discriminators and a base-mint comparison at offset 136; `dataSlice` returns no account data. It does not scan the entire program without filters. Responses remain bounded to 1 MiB and candidate selection to eight addresses. Each candidate passes the full owner/layout/config/PDA reader and must have the requested base mint. Multiple validated matches produce an explicit user choice; no arbitrary pool is selected. Temporary discovery-provider failure offers Retry or direct pool input rather than inventing a report.

Reports preserve `inputAddress` and resolution kind, source, input slot and candidate count. Canonical share links use the resolved pool and require a fresh inspection. The original account and subsequent pool/config/mint reads are confirmed sequential observations, not an atomic snapshot. A known DBC mint may still be undiscoverable through an RPC provider that disables the required filtered query.

Operator-only RPC lists are ordered, deduplicated and capped at four. A nonempty `MAINNET_RPC_URLS` / `DEVNET_RPC_URLS` list takes precedence over the matching single URL. Transient HTTP 429/5xx, timeouts and designated unhealthy/context errors receive one retry per endpoint; invalid accounts and non-transient errors are not retried. Each retry operation shares a 45-second deadline; bounded fetch also covers response-body reading. The API applies an outer 50-second deadline across discovery and inspection and propagates cancellation to all work.

Official public mainnet/devnet endpoints share a bounded 2-requests/second process queue (maximum 64 waiting requests). Cooldown and backoff honor bounded Retry-After inside the operation deadline; cancellation removes queued work. An operator may override pacing with `RPC_REQUESTS_PER_SECOND`; private endpoints are unpaced by default. Exhausted upstream quota is reported as HTTP 429 with Retry-After, not as a finding about the pool. Provider availability can still prevent an inspection.
